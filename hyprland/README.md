# Hyprland

Lua config via the `hl` API (tested on Hyprland 0.56.2). Entry point: `~/.config/hypr/hyprland.lua`,
which just `require`s the modules below in order.

```
modules/
├── appearance/look.lua        gaps, borders, blur, animations
├── colors/colors.lua          generated palette (matugen)
├── environment/env.lua        env vars (PATH, cursor, portals)
├── hardware/input.lua         dofile -> input.local.lua
├── hardware/monitors.lua      dofile -> monitors.local.lua, exports hardware facts
├── interaction/binds.lua      keybinds
├── interaction/rules.lua      window / layer rules (incl. agent windows)
├── interaction/zen_mode.lua
├── meta/hl.meta.lua           autogenerated Lua API stubs (do not edit)
└── programs/                  autostart + program commands
```

Reload with `hyprctl reload`. Test any dispatcher / inspect the compositor from the shell
with `hyprctl repl '<lua expression>'` (e.g. `hyprctl repl 'return hl.get_active_monitor().name'`).

## Machine-local hardware config

Two files must be created manually on each machine (gitignored, `.sample` versions shipped
next to them):

### `~/.config/hypr/modules/hardware/monitors.local.lua`

`monitors.lua` `dofile`s this file, so it does the actual `hl.monitor` / `hl.workspace_rule`
calls, and **returns a table with the facts the versioned modules need** (today:
`agents_monitor`). That is how the rest of the config avoids hardcoding output names.

Find output names with `hyprctl monitors`.

```lua
-- Monitor where the agents scratchpad lives (SUPER + A)
local agentsMonitor = "HDMI-A-1"

hl.monitor({
    output = "HDMI-A-1",
    mode = "2560x1080",
    position = "1080x485",
    scale = "1",
})

hl.monitor({
    output = "DP-3",
    mode = "preferred",
    position = "0x0",
    scale = "auto",
    transform = 3,          -- 3 = 270°, vertical monitor
})

-- Workspaces
for i = 1, 5 do
    hl.workspace_rule({ workspace = i, monitor = "DP-3", persistent = true })
end

for i = 6, 10 do
    hl.workspace_rule({ workspace = i, monitor = "HDMI-A-1", persistent = true })
end

hl.workspace_rule({
    workspace = "special:agents",
    monitor = agentsMonitor,
    layout = "scrolling",
})

-- Facts consumed by the versioned modules (see modules/hardware/monitors.lua)
return {
    agents_monitor = agentsMonitor,
}
```

| Field | Used by | Meaning |
|-------|---------|---------|
| `agents_monitor` | `interaction/binds.lua` (SUPER + A), agent window rules | Output that owns `special:agents`. If `nil`, SUPER + A falls back to plain Hyprland behaviour (toggle on the focused monitor). |

### `~/.config/hypr/modules/hardware/input.local.lua`

```lua
hl.device({
    name = "your-keyboard-name",  -- find with: hyprctl devices
})

hl.device({
    name = "your-mouse-name",
    sensitivity = -0.5
})
```

For Apple Silicon (Asahi), see the `input.lua` history for the trackpad + gesture config.

## Agent workspace (SUPER + A) — why the bind is not a plain dispatcher

Hyprland has no per-monitor special workspaces. `toggle_special` always assigns the
workspace to the **focused** monitor (`ConfigActions::toggleSpecial` ->
`CMonitor::setSpecialWorkspace` does `pWorkspace->m_monitor = m_self`), so every window in
it travels to that monitor and gets re-tiled / re-scaled there. Toggling agents while
focused on the second monitor therefore destroys the layout of the agent windows.

`binds.lua` works around it by anchoring the toggle to `agents_monitor`:

- closed -> focus the owner monitor, then toggle (opens there)
- open on the owner -> toggle, then return focus to the monitor you came from
- open on some other monitor (stolen) -> focus the owner and toggle, which re-anchors it

If `agents_monitor` is `nil` or the output is unplugged, it degrades to the plain
Hyprland behaviour instead of doing nothing.

## Wallpaper

`scripts/randomize-wallpaper.sh` (at `hyprland.start`, and on `SUPER + SHIFT + W`) picks
an image from `~/Pictures/wallpapers/rotation` — never the one already on screen — applies
it to every monitor and re-themes the desktop with `set-theme`. Pass a directory as `$1`
to rotate over something else.

`~/.config/hypr/hyprpaper.conf` is **generated, not versioned**: the script rewrites it
from the live monitor list right before starting hyprpaper. hyprpaper has no wildcard
monitor, so a stale entry silently leaves that output without a wallpaper — that is why
the config is derived instead of hand-edited. Editing it by hand does nothing, the next
session overwrites it.

If hyprpaper is already running the script hot-swaps over its IPC (`~0.1s`). Otherwise it
writes the config and starts hyprpaper itself, so the first image drawn is already the
chosen one instead of a leftover (`~0.4s` to first wallpaper on this machine). That is
also why `hyprpaper` is no longer in `autostart.lua`.
